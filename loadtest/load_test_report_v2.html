GCP Cloud Run 實測數據

容器執行個體數量（Active + Idle）

11:50 基準線 2 idle instances = min-instances=2 生效， 系統在測試開始前就有暖機實例待命，消除 Cold Start。 200-user 測試擴展至 7 instances， 500-user 測試擴展至 12 instances。

要求數 — Cloud Run 伺服器端（req/s）

結論

🏆

優化成效顯著

  • 500-user 失敗率從 5.2% 降至 0%：Connection Pool 縮小避免 Cloud SQL 連線耗盡
  • p95 全面改善 58–69%：min-instances=2 消除 Cold Start 初期飆升
  • p99 降低 78%（6,800ms → 1,500ms）：尾部延遲大幅收斂
  • 全三輪零失敗：系統在壓測範圍內完全穩定
📈

Auto-Scale 行為分析

  • 基準 2 instances 待命（min-instances=2），無 Cold Start
  • 200-user 測試 → 擴展至 7 instances
  • 500-user 測試 → 擴展至 12 instances
  • 更小的 pool_size 使每個 instance 負載更輕，Cloud Run 更積極 scale out
  • 無任何 5xx（伺服器端錯誤）出現於 GCP 監控
🔧

仍可繼續改善

  • 500-user p50 = 200ms（v1 為 80ms）：pool 縮小後部分請求等待連線，可透過 Redis Cache 消除重複 DB 查詢
  • Dashboard 端點 p95 最高（920ms）：Redis Cache TTL=30s 可將命中率提升至 >90%
  • 若需支援 50,000+ 員工，建議啟用 Cloud SQL Read Replica
